Heuristics in TRACEY

A heuristic is a rule that is frequently correct, but not always. TRACEY uses heuristics to find probable patterns. The Bitcoin blockchain records amounts, addresses, transactions and times. It does not record names, wallets, companies or intentions. All other data that TRACEY adds is a guess. These guesses come from the usual structure of transactions.

A heuristic is not proof. It is frequently correct, but it can be very wrong. Some users and privacy tools make transactions that break heuristics intentionally. Use each heuristic only as a lead. Compare it with other evidence, for example court records, answers from exchanges or attributions. Do not state it as a fact.

Facts (from the blockchain)Addresses, amounts, transaction IDs, dates and times, address types, and the movement of coins from one address to an other address.
Guesses (heuristics)Probable change, wallet tags (common ownership), cj (coinjoin), B/E/S (business, exchange or service), wallet software, fingerprints and peel chains.

Change (“show change”)

When a wallet makes a payment, it usually sends the remaining amount back to the sender. This new output is the “change”. If you know which output is the change, you know where the money of the sender went next.

Rules

TRACEY examines only transactions with exactly two outputs. The change output is the output that:

  1. goes back to one of the input addresses of the transaction. If no output does this:
  2. is the only output with the same address type as the inputs. All inputs must have one type, and the other output must have a different type. If no output does this:
  3. is not a round amount when the other output is a round amount (a multiple of 0.001 BTC).

If these rules do not give one clear result, TRACEY does not mark an output. A grey dashed line shows a change output.

Limits

These conditions cause incorrect results: wallets that send change to the same address type as the payment, PayJoins, and change with a round amount. Many new wallets make the change type the same as the payment type. They do this to prevent this guess.

Sources: Bitcoin Wiki: Privacy, change address detection · Meiklejohn et al. (2013): A Fistful of Bitcoins · Ishaana Misra (2023): Wallet Fingerprints

Common ownership (“show common ownership”)

To spend coins, a wallet must sign each input. Thus, the addresses that pay into the same transaction usually belong to one wallet. This is the oldest heuristic in blockchain analysis. Analysts also use it more than all other heuristics.

Rules

  • TRACEY counts all input addresses of a transaction as one wallet. This includes inputs that the graph does not show.
  • The links connect. For example, A and B are in one transaction, and B and C are in a different transaction. Then A, B and C are one wallet.
  • TRACEY does not use transactions that look like a coinjoin (see below). The inputs of a coinjoin belong to different persons.
  • Each wallet in the graph that these rules apply to gets a tag (“wallet A”) and its own colour. The tag and the colour show on its addresses and lines.

Limits

A coinjoin puts the coins of many unrelated persons into one transaction. If TRACEY does not identify a coinjoin, common ownership puts these persons into one wallet. This error then moves along the links to more addresses. PayJoins break the rule intentionally. Exchanges spend the deposits of many customers together. Thus, one “wallet” can be one company, not one person.

Sources: Satoshi Nakamoto (2008): Bitcoin whitepaper, section 10 · Bitcoin Wiki: Common-input-ownership heuristic · Meiklejohn et al. (2013): A Fistful of Bitcoins

coinjoin (“show coinjoin”)

A coinjoin is a privacy transaction. Many persons put their coins into one transaction, so it is difficult to know which coins went where. Some designs (for example Whirlpool or JoinMarket) give each person the same output amount. Other designs, for example WabiSabi (Wasabi Wallet), use many different amounts and mix them.

Rules

TRACEY uses the coinjoin rule of mempool.space. All of these conditions must be true:

  1. The transaction has a minimum of 5 inputs and 5 outputs.
  2. The number of different input amounts plus the number of different output amounts is a maximum of half of all inputs and outputs.
  3. No output address occurs two times. This includes an output address that is also an input address.
  4. The transaction has no inscription and no OP_RETURN output.
  5. The ratio of inputs to outputs is between 1:5 and 5:1.

A transaction that agrees with these rules gets a yellow “cj” badge. TRACEY never uses coinjoins for common ownership. This is true when you select the “show coinjoin” box and when you do not select it. TRACEY finds inscriptions from their standard marker. mempool.space does a full analysis of inscriptions.

Limits

The mempool.space code calls this rule a “fast but bad heuristic”. It does not find coinjoins with many different amounts or with fewer than 5 persons. It can incorrectly mark usual payouts that have many equal amounts.

Sources: mempool.space source code: getTransactionFlags (common.ts) · Bitcoin Wiki: coinjoin

B/E/S: probable business, exchange or service

Analysis companies and researchers usually do not identify exchanges from one pattern. They start with addresses that they know belong to an exchange. These addresses come from their own test deposits and withdrawals, from published addresses and from court records. Then they use common ownership to find more addresses. TRACEY cannot know the start addresses of an exchange. You must supply them as labels.

Rules

An address gets the purple B/E/S badge when one of these conditions is true:

  1. Large payout: the address spends in a transaction that pays more than N outputs of 2 or more different address types. The setting “exchange / service: pays > N outputs” sets N (default 20). TRACEY marks all input addresses of that transaction. It does not follow the outputs of that payout. TRACEY made this rule from the patterns of batch payouts.
  2. Same wallet: when you select “show common ownership”, the badge also goes to each address in the same wallet group as a marked address.

TRACEY does not use the number of transactions of an address for this rule. That number only sets when TRACEY stops at an address. Put the pointer on the badge to see which rule applies.

Limits

A person or a mining pool that pays many persons at the same time looks like a large payout. A large coinjoin can also look like a large payout. When the badge goes along common ownership, it also takes all the errors of that heuristic. TRACEY does not find services that do not pay many outputs in one transaction.

Behavioral fingerprint (“show behavioral fingerprint”)

A behavioral fingerprint shows that transactions probably come from the same wallet software or setup. It does not show the same person or the same wallet. Unusual fingerprints with rare custom setups can show the same service. Behavioral heuristics are the least reliable heuristics.

Each wallet program sets the technical details of a transaction in its own way. These details include the version number, the locktime, the sequence numbers, the order of inputs and outputs, and the change. These default settings can show which software made a transaction.

Known wallet software (teal tag)

TRACEY removes wallets from the list one at a time. It removes a wallet when the transaction has a property that the wallet never makes with its default settings. The wallets that remain are the result. If 3 or fewer wallets remain, the tag shows all of them (“Bitcoin Core or Sparrow”). If 4 or more wallets remain, there is no tag.

This examination needs one more request for each input. Trezor Suite and BitBoxApp make transactions in the same way. Thus, TRACEY always shows them together. Wasabi Wallet is in the list, but TRACEY never shows a Wasabi tag. Wasabi intentionally makes its usual transactions look like usual network traffic: version 2, a random locktime that is usually 0, and no RBF signal. In a test on 1,500 recent transactions, a Wasabi tag matched 214 transactions. Almost all of them were the most usual type of transaction. Thus, the tag shows mostly other software. The coinjoin rule still finds Wasabi coinjoins. Coldcard is not in the list. It only signs transactions that other software makes (for example Sparrow or Electrum). Thus, its transactions show the fingerprint of that software. The rules for address reuse, OP_RETURN and Taproot spends come from the 2023 study by Misra. Exodus, Coinbase Wallet and Trust Wallet are not in the list. Their code is not public, and only data from 2023 is available.

The profile contains the traits that all of these transactions of the wallet have. Two or more wallets get the same “fingerprint” tag when they have the same traits. The number of these traits must be equal to or more than the setting (default 9/9). TRACEY does not use coinjoins.

Limits

Profiles show the default settings of specific versions. Users can change settings, and wallets change their defaults. Wallets that are not in the list can look like a wallet in the list. The tag means “behaves like”, not “is”. In the study by Misra, one transaction identified its wallet in approximately half of the cases.

Peel chain (“show peelchains”)

In a peel chain, the owner spends a large coin again and again. Each transaction pays out (“peels off”) a smaller amount. It sends the larger remaining amount to a new address. The next transaction spends that address in the same way. Services that pay customers make peel chains. Persons who move money in steps also make them. Frequently, automatic software makes these transactions.

Rules

  • A transaction is a link when it has exactly 1 input and 2 outputs.
  • TRACEY finds the change output of the link with the “show change” rules. The next link is the transaction in the graph that spends this change output. That transaction must also be a link.
  • The next link must have the same wallet settings as the link before it: the same version, the same type of locktime (0 or a block height) and the same nSequence value. The same wallet usually spends its own change, so its settings stay the same.
  • If the rules do not find one clear change output, or if the settings are different, the chain stops at that transaction.
  • TRACEY marks a sequence of links as one chain when the sequence has the minimum length or more. You set the minimum length next to “show peelchains” (default 3). Each transaction gets an indigo tag “peel 1, 2, …” with its hop number.
  • Put the pointer on the tag to see the length of the chain, the total amount peeled off and the number of blocks. You also see if all fee rates are whole numbers. Whole-number fee rates are a sign of automatic software.

Limits

TRACEY finds only chains that the graph shows. Expand transactions to follow a chain farther. This heuristic depends on the change guess of the “show change” rules. If that guess is incorrect, the chain follows the receiver and not the sender. Then the chain and the total amount peeled off are incorrect. The “show change” rules frequently find no clear change output. Thus, TRACEY can miss chains or show them shorter than they are. Many wallets use the same default settings, so the settings check cannot tell them apart. Wasabi Wallet uses a random locktime, so its chains can stop early. The papers below use different change rules: Meiklejohn et al. use new (one-time) addresses. Kappos et al. use the usual behavior of each wallet. TRACEY uses only a simple part of this: it compares the settings of each link with the next link. A person who makes many usual payments in a sequence from one coin looks the same.

Sources: Meiklejohn et al. (2013): A Fistful of Bitcoins (peeling chains) · Kappos et al. (2022): How to Peel a Million

Trace settings (not heuristics)

These settings control what the graph shows. They are limits. They are not guesses about the owner of an address.

  • batch > N outputs: for transactions with more outputs, the graph shows only some outputs. These are the outputs to addresses that are already in the graph or in your list. The other outputs are in “+ N hidden”.
  • stop at > N tx: TRACEY does not follow addresses with more transactions. Click + to load 10 transactions at a time.
  • dust below N sats: the graph shows very small outputs, but TRACEY does not follow them.
  • max addresses: this is the maximum size of the graph. It is a safety limit.

Trace loading, fetching transactions

Type Bitcoin addresses or transaction IDs. You can also type labels. TRACEY traces each address in the list. For a transaction ID, TRACEY shows the addresses that paid into it and the sources of those coins (one hop back). It also traces each output forward. You can paste a list with one address on each line. After an address, you can add a comma and a label.
